# Smooth Vertex Morphing System

## Overview

The 3D object now **smoothly morphs** between different geometric shapes using **vertex-based interpolation**. Instead of instantly switching geometries, each vertex gradually moves from one position to another, creating fluid, organic transitions.

## How It Works

### 1. Base Geometry
All shapes are based on `IcosahedronGeometry` with the same vertex count:
```tsx
<icosahedronGeometry args={[1, 3]} />
// 3 subdivisions = consistent vertex count across all shapes
```

This ensures every shape has the **same number of vertices**, which is critical for smooth morphing.

### 2. Shape Generation Functions

Each shape is generated by transforming the base icosahedron vertices:

**Torus Knot** (`createTorusKnotPositions`)
- Uses parametric equations: `p=2, q=3`
- Creates intertwined tubular structure
- Vertices follow knot curve in 3D space

**Sphere** (`createSpherePositions`)
- Simple icosahedron at radius 1.2
- Natural spherical distribution

**Octahedron** (`createOctahedronPositions`)
- Uses distance formula: `|x| + |y| + |z| = constant`
- Creates diamond-like crystalline structure
- Sharp edges and flat faces

**Torus** (`createTorusPositions`)
- Major radius (R): 1.0
- Minor radius (r): 0.4
- Vertices arranged in ring formation

### 3. Morphing Logic

On every frame, the system:

1. **Determines current section** based on scroll progress (0-1)
2. **Identifies source and target shapes** for that section
3. **Calculates local morph progress** (0-1 within each 25% section)
4. **Applies easing function** for smooth acceleration/deceleration
5. **Interpolates vertex positions** using `THREE.MathUtils.lerp()`

```tsx
// Example: morphing from sphere to octahedron at 40% scroll
scrollProgress = 0.40
section = 0.25 to 0.5  // Second quarter
localProgress = (0.40 - 0.25) / 0.25 = 0.60  // 60% through transition
easedProgress = easeInOutCubic(0.60) = 0.784  // Smooth easing

// For each vertex:
newPosition = lerp(sphereVertex, octahedronVertex, 0.784)
```

### 4. Easing Function

Uses **cubic easing** (ease-in-out) for natural motion:

```tsx
function easeInOutCubic(t: number): number {
  return t < 0.5
    ? 4 * t * t * t  // Ease in (slow start)
    : 1 - Math.pow(-2 * t + 2, 3) / 2  // Ease out (slow end)
}
```

This creates smooth transitions:
- **Slow start**: Morphing begins gradually
- **Fast middle**: Quick transformation in the middle
- **Slow end**: Settles smoothly into final shape

## Morphing Timeline

### 0-25% Scroll: Torus Knot → Sphere
- Complex knot unwinds
- Curves smooth out
- Shape becomes spherical

### 25-50% Scroll: Sphere → Octahedron
- Smooth sphere deforms
- Flat faces emerge
- Sharp edges crystallize

### 50-75% Scroll: Octahedron → Torus
- Crystal structure opens up
- Center becomes hollow
- Forms ring shape

### 75-100% Scroll: Torus (Complete)
- Maintains final torus form
- Continues rotating and animating
- Ready to loop back if needed

## Performance Optimizations

### 1. Pre-computed Geometries
All shape positions are calculated once during initialization:
```tsx
const morphData = useMemo(() => {
  return {
    torusKnot: createTorusKnotPositions(3),
    sphere: createSpherePositions(3),
    octahedron: createOctahedronPositions(3),
    torus: createTorusPositions(3),
  }
}, [])
```

### 2. Efficient Interpolation
- Direct array access (no object creation)
- Single loop through vertices
- Only updates when necessary

### 3. Normal Recalculation
```tsx
geo.attributes.position.needsUpdate = true
geo.computeVertexNormals()
```
Normals are recalculated every frame for correct lighting on morphing surfaces.

### 4. Subdivision Level
`subdivisions: 3` provides good balance:
- **Lower (1-2)**: Faster but blocky transitions
- **Higher (4+)**: Smoother but more expensive
- **Current (3)**: Optimal for most devices

## Customization

### Change Easing Function

Replace `easeInOutCubic` with other easing functions:

```tsx
// Linear (no easing)
function linear(t: number): number {
  return t
}

// Bounce effect
function easeOutBounce(t: number): number {
  const n1 = 7.5625
  const d1 = 2.75
  if (t < 1 / d1) return n1 * t * t
  else if (t < 2 / d1) return n1 * (t -= 1.5 / d1) * t + 0.75
  else if (t < 2.5 / d1) return n1 * (t -= 2.25 / d1) * t + 0.9375
  else return n1 * (t -= 2.625 / d1) * t + 0.984375
}

// Elastic snap
function easeOutElastic(t: number): number {
  const c4 = (2 * Math.PI) / 3
  return t === 0 ? 0 : t === 1 ? 1
    : Math.pow(2, -10 * t) * Math.sin((t * 10 - 0.75) * c4) + 1
}
```

### Adjust Transition Speed

Change how much of each section is dedicated to morphing:

```tsx
// Faster transitions (morph in first 10% of each section)
if (scrollProgress < 0.25) {
  morphProgress = Math.min((scrollProgress % 0.25) / 0.10, 1)
}

// Slower transitions (use entire section for morphing)
if (scrollProgress < 0.25) {
  morphProgress = (scrollProgress % 0.25) / 0.25
}

// Delayed start (morph in last 50% of section)
if (scrollProgress < 0.25) {
  const local = scrollProgress % 0.25
  morphProgress = local < 0.125 ? 0 : (local - 0.125) / 0.125
}
```

### Add More Shapes

To add a 5th shape:

```tsx
// 1. Create shape generation function
function createIcosahedronPositions(subdivisions: number): Float32Array {
  const geo = new THREE.IcosahedronGeometry(1.2, subdivisions)
  return geo.attributes.position.array as Float32Array
}

// 2. Add to morphData
const morphData = useMemo(() => {
  return {
    torusKnot: createTorusKnotPositions(3),
    sphere: createSpherePositions(3),
    icosahedron: createIcosahedronPositions(3),  // NEW
    octahedron: createOctahedronPositions(3),
    torus: createTorusPositions(3),
  }
}, [])

// 3. Update morphing logic (5 sections = 20% each)
if (scrollProgress < 0.2) {
  sourceShape = morphData.torusKnot
  targetShape = morphData.sphere
  morphProgress = (scrollProgress % 0.2) / 0.2
} else if (scrollProgress < 0.4) {
  sourceShape = morphData.sphere
  targetShape = morphData.icosahedron  // NEW
  morphProgress = ((scrollProgress - 0.2) % 0.2) / 0.2
} else if (scrollProgress < 0.6) {
  sourceShape = morphData.icosahedron  // NEW
  targetShape = morphData.octahedron
  morphProgress = ((scrollProgress - 0.4) % 0.2) / 0.2
}
// ... continue pattern
```

### Change Subdivision Quality

Higher subdivisions = smoother morphing but lower performance:

```tsx
// Low quality (faster)
const subdivisions = 1  // Blocky but fast

// Medium quality (balanced)
const subdivisions = 2  // Good for mobile

// High quality (current)
const subdivisions = 3  // Great for desktop

// Ultra quality (slower)
const subdivisions = 4  // Very smooth, high-end only
```

## Debugging

### Visualize Morph Progress

Add to the `useFrame` function:

```tsx
if (scrollProgress > 0) {
  console.log({
    scroll: scrollProgress.toFixed(3),
    section: Math.floor(scrollProgress / 0.25),
    localProgress: morphProgress.toFixed(3),
    easedProgress: easedProgress.toFixed(3)
  })
}
```

### Check Vertex Count

Ensure all shapes have same vertex count:

```tsx
console.log({
  torusKnot: morphData.torusKnot.length / 3,
  sphere: morphData.sphere.length / 3,
  octahedron: morphData.octahedron.length / 3,
  torus: morphData.torus.length / 3,
})
// All should be equal (e.g., 642 vertices with subdivision 3)
```

### Monitor Performance

```tsx
const startTime = performance.now()
// ... morphing code ...
const endTime = performance.now()
if (endTime - startTime > 16) {  // > 1 frame at 60fps
  console.warn('Morphing took', endTime - startTime, 'ms')
}
```

## Known Limitations

1. **Vertex count must match**: All shapes must have same number of vertices
2. **Topology constraints**: Can't morph between drastically different shapes perfectly
3. **Performance impact**: Updating geometry every frame is expensive (but optimized)
4. **Sharp edges**: Some shapes (like octahedron) may look approximate due to icosahedron base

## Advanced Techniques

### Morph Attributes
You can also morph other attributes:

```tsx
// Morph colors
const sourceColors = new Float32Array([...])
const targetColors = new Float32Array([...])
for (let i = 0; i < colors.length; i++) {
  colors[i] = THREE.MathUtils.lerp(sourceColors[i], targetColors[i], easedProgress)
}
geo.attributes.color.needsUpdate = true

// Morph UVs (texture coordinates)
const sourceUVs = new Float32Array([...])
const targetUVs = new Float32Array([...])
for (let i = 0; i < uvs.length; i++) {
  uvs[i] = THREE.MathUtils.lerp(sourceUVs[i], targetUVs[i], easedProgress)
}
geo.attributes.uv.needsUpdate = true
```

### Multi-stage Morphing
Create intermediate shapes for smoother transitions:

```tsx
// Instead of: Sphere → Octahedron
// Use: Sphere → Rounded Octahedron → Sharp Octahedron

const intermediateShape = morphData.sphere.map((val, i) =>
  THREE.MathUtils.lerp(val, morphData.octahedron[i], 0.5)
)
```
